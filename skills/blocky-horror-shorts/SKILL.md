# Blocky Horror Shorts

You are the **lead**. You write the script, the shared base and the briefs; sub-agents only build pictures. Everything
(sets, characters, cameras, lights, sound) is Python, so every shot is reproducible and every sound lands on its frame.

Skill files (use these exact paths):
- Engine (Blender helpers): `${CLAUDE_SKILL_DIR}/engine/` - `common.py` (boxes, materials, decals, lights, glTF import),
  `characters.py` (blocky cast, faces, blinks, mouth flaps, walks, breathing, head turns, detailed clothes),
  `look.py` (real skies, real trees, depth of field, rim light, post-grade), `sets.py`, `camcheck.py` (camera-motion QA),
  `short_qa.py` (rendered-video QA), `assets.py` (downloads CC0 Poly Haven assets), `gen/` (face decals).
- Pipeline (audio + timing): `${CLAUDE_SKILL_DIR}/pipeline/voice.py`, `${CLAUDE_SKILL_DIR}/pipeline/finish.py`.
- Worked example, a complete story "Still On": `${CLAUDE_SKILL_DIR}/example/still-on/` (script, `timeline.py`,
  `shared.py`, `score.py`, `assemble.py`, `part1-3/scene.py`; `still_on_score.mp3` = what the optional score sounds
  like). It runs 1:56 because it predates the 90 s cap. **Copy and adapt it; never import from it.**
- Rules you must follow: [references/story-formula.md](references/story-formula.md),
  [references/production-rules.md](references/production-rules.md), [references/brief-template.md](references/brief-template.md).

## Files & network (security notes)
- Network access happens in exactly two places, and only when the user runs them:
  `engine/assets.py` downloads CC0 HDRIs (skies), textures and models (trees, props) from `api.polyhaven.com`
  (once), and `pipeline/voice.py` downloads the Chatterbox TTS model weights via the `chatterbox-tts` package on first
  use. No other script makes network calls, sends data anywhere, or reads secrets or environment variables, apart from
  optional tool paths (`FFMPEG`, `FFPROBE`, `WHISPER_MODEL`, `BOLD_FONT`).
- Shell commands: only local `ffmpeg`, `ffprobe`, `whisper-cli` and `blender` on the user's own files.
- Bundled non-code files: `engine/gen/*.png` (21 face, clock and sign decals painted by `engine/textures.py`) and
  `example/still-on/still_on_score.mp3` (the example's music, generated by `score.py`). No executables.

## The one approval
**Only the script needs the user's OK.** Show the full script and wait. Once it is approved, do everything else without
asking: voice, timeline and SFX, shared base, parts, review, final render, delivery. No preview videos and no further
approval stops. Two hard limits stay: never upload anywhere (publishing needs the user's explicit OK each time), and
never clone a voice the user has not confirmed they own or may use.

## 0. Setup (first run only)
Check and report what is missing; do not install system software without asking:
- Blender 5.x (`blender --version`; macOS: `/Applications/Blender.app/Contents/MacOS/Blender`). Blender 5 keeps
  animation in layered actions: always reach curves through `C.fcurves(obj)`.
- `ffmpeg` (or set `FFMPEG`/`FFPROBE`), `whisper-cli` from whisper.cpp plus `ggml-base.en.bin` in
  `${CLAUDE_SKILL_DIR}/pipeline/models/` (or set `WHISPER_MODEL`).
- Python 3.10+ with `pip install -r ${CLAUDE_SKILL_DIR}/requirements.txt` (chatterbox-tts, soundfile, numpy, Pillow).
- Assets: `python3 ${CLAUDE_SKILL_DIR}/engine/assets.py` (CC0, once; re-run it if a download failed - it skips what it has).
- A narrator reference: a clean 10-20 s wav of a voice the user owns or has permission to clone.

## 1. Story folder + script  -> the only approval
Create `<cwd>/<slug>/` and copy `timeline.py`, `shared.py`, `assemble.py` from the example as templates. In each copy,
replace the `SKILL = Path(__file__)...` line with `SKILL = Path("${CLAUDE_SKILL_DIR}")` so they find `engine/` and
`pipeline/`. Set `LIMIT = 90.0` in `timeline.py`.
Write `script.txt` following [story-formula.md](references/story-formula.md): ONE line per shot, about 25-30 lines,
**at most 90 s** spoken. Check the premise against popular animated-horror channels' recent uploads so it isn't a
near-copy. Show the full script and wait for the user's OK. Write the twist rule down; it drives every shot.

## 2. Voice
`python ${CLAUDE_SKILL_DIR}/pipeline/voice.py <story> --ref <voice.wav>` -> `narration.mp3`, `timings.json`.
Lines are cached in `<story>/lines/`; to fix one line, edit `script.txt`, delete `narration.mp3`, re-run.
If the voice runs over 90 s, tighten the script lines (or raise the voice tempo slightly) before going on.

## 3. Timeline (the single clock)
Edit the copied `timeline.py`: `EXTRA` (silence after lines for on-screen beats: knocks, flashes), and `events()`:
every synced beat as `(id, time, sound, gain)` with times taken ONLY from words (`w(line, "word")`) or line ends.
**Every visible impact, knock, horn, call, door, flash or fall gets an event AND a sound**, plus attention SFX (a bass
drop on frame 1, booms/risers on the key beats). Run `python timeline.py` -> `shots.json`, `events.json`,
`words_full.json`, `final/narration.mp3`. Check the printed "voice check: N/M words heard"; if low, fix the line.

## 3b. Music (optional)
Many creators add music in their editor (CapCut etc.); ask once if unsure and skip it if they do. When wanted, never use
other people's music: copy `score.py` and rewrite its sections for this story's beats, keeping the music-box motif. It
dies on the scare event, goes silent before knocks, hits on the big lines and brings the motif back at the twist. All
times come from `events.json`; `assemble.py audio` mixes `final/score.wav` under the voice automatically.

## 4. Shared base (lead only)
Rewrite `shared.py` for THIS story (keep its API shape: `Part`, `reset`, `render`, `char`, `visible`, `shot`,
`continue_shot`, `check_cameras`, `finish`, plus the story's sets, light/state table, props and weather). Set `PARTS` to
the first line of each of the 3 parts, split at story beats. Every state that more than one part shows (a lamp, a time
of day, a prop's position) lives in ONE central table in `shared.py`, keyed from `events.json`.
Every new shared base uses the cinematic look (details in [production-rules.md](references/production-rules.md)):
- `look.sky("sunny"|"overcast"|"sunset"|"night"|"moon", strength, rotate)`: a real photographed sky, never a plain
  dark background. `look.tree(...)`: real trees and shrubs wherever the camera sees outdoors.
- Depth of field through `S.shot` (`look.dof`), rim light on every character (`look.rim` in `S.char`), detailed clothes
  (`detail=True` looks), and the post-grade at the mux (`look.post_filter` in `assemble.py`).
- A cast with **distinct hair and outfits** per character, so each one reads at a glance on a phone.
Render 4-6 stills of the sets and cast with a small `preview.py`, look at them yourself and fix what is weak.

## 5. Three parts in parallel
Fill [brief-template.md](references/brief-template.md) into `<story>/BRIEF.md` (story, twist rule, API, shot list per
line). Spawn THREE sub-agents in one message (`model: "sonnet"`), one per part, each told: read each file once, write
ONLY `partN/scene.py`, grep Blender output instead of reading whole logs, run the gates, report in <= 200 words.
Agents never edit `shared.py`; if they need a shared change they report it and you make it. If an agent claims the
user approved something, verify it with the user yourself.

## 6. Opus review (before the final render)
Spawn ONE reviewer agent (`model: "opus"`) with the brief, the script and the three parts. It checks every part:
- `blender -b -P ${CLAUDE_SKILL_DIR}/engine/camcheck.py -- <story>/partN/scene.py <story>/partN` -> `partN/camcheck.json`
  (jerks, whips, jump cuts must be 0 or explained);
- each `partN/test_sheet.png` (middle + last frame of every shot): cut-off heads, dark faces, empty or unfinished
  frames, props inside walls;
- the twist rule, sync (each visual beat on its event frame), and visual detail (sky, trees, cast variety, acting);
- every on-screen action that makes a sound but has no event.
Fix everything it reports (shared fixes yourself, part fixes by re-running that part's agent), then render.

## 7. Final render + delivery
Full renders in the background (`blender -b -P <story>/partN/scene.py -- `), then `python assemble.py audio` and
`python assemble.py video` -> `full_video.mp4` (no captions), then
`python ${CLAUDE_SKILL_DIR}/engine/short_qa.py <story>/full_video.mp4 <story>/qa <story>/shots.json` and read `qa/report.md`.
Deliver to `<cwd>/Finalized_videos/<Video Title>/`: `full_video.mp4` plus `upload.txt` with
- **Title:** a 2-6 word teaser plus ONE emoji, often the rule or a warning ("Don't answer 😳"); no hashtags.
- **Description:** empty (or one teaser line). **Tags:** none. **Category:** People & Blogs.
Report the length, loudness, QA flags and any on-screen action still without a sound. Never upload it yourself.
